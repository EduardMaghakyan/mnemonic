## Mnemonic v0.3.0

The biggest release since v0.1.0 — four feature lines on top of the v0.2.x foundation. All new functionality is either opt-in or transparently improves the existing flow; existing daily notes, audio storage, and the CLI are unchanged.

If you're on v0.2.1 today, this is a drop-in upgrade.

### What's new

#### Image attachments — Gemma 4 reads what you see

Take a screenshot, then record. Gemma 4 E4B reads the audio *and* the image in a single forward pass and produces one bullet that combines both. Two flows, your pick:

**One-shot screenshot + voice** — default combo `Ctrl+Option+Cmd+Space`:

1. Press the hotkey. macOS shows the region-select crosshair.
2. Drag a region. Recording starts the moment you release.
3. Press your usual voice hotkey (or the screenshot combo again) to stop. `Escape` during region-select cancels — no recording.

**Auto-attach from clipboard** — same voice hotkey as a plain recording:

1. Take a screenshot to the clipboard (`Ctrl+Shift+Cmd+4`, hold Ctrl to suppress the desktop file).
2. Hit your voice hotkey and narrate. A notification confirms *"Recording with screenshot attached."*

Both flows land a bullet with the embed and either OCR or a one-line caption underneath:

```markdown
- 14:35 Look at this — the merge_chunks panic finally reproduces. [audio](../audio/2026-05-13/143500.wav)

  ![](../audio/2026-05-13/143500.png)

  ```text
  thread 'main' panicked at 'index out of bounds: the len is 0 but the index is 0'
  src/merge.rs:42:18
  ```
```

The PNG is saved next to the WAV at `~/Mnemonic/audio/YYYY-MM-DD/HHMMSS.png`. The image rides inside the same loopback-only request as the audio — no external network call.

#### Recording queue — no more waiting for the model

Recording is now decoupled from structuring. The moment you stop talking, the WAV (and any attached PNG) lands in `~/Mnemonic/inbox/<timestamp>/` and the tray icon returns to gray. **You can fire off the next recording immediately** even while llama-server is still working on the previous one.

A background worker drains the inbox serially; bullets stream into the daily note as they complete. The tray menu shows queue depth at the top (`Queue: idle` or `Queue: N waiting`).

Crash recovery is free: if Mnemonic quits or your laptop sleeps with jobs in flight, they stay on disk. On next launch the worker picks up exactly where it left off — no manual `mnemonic redo` needed for the common case.

The `RecorderState::Processing` yellow tray state is gone; the icon is now binary (gray = idle, red = recording).

#### Intent routing to macOS Shortcuts — opt-in

When enabled, Mnemonic forks the transcribed text through a second, fast Gemma 4 call (~1.7s warm) that detects whether your note is asking the OS to do something — *"remind me to call Sarah at 3 PM"*, *"schedule a 1:1 with Priya for Thursday at 4"* — and if it is, fires a macOS Shortcut you've defined. Opt-in, whitelisted, undoable.

The architecture is deliberately conservative:

- **Off by default.** Recordings never hit the intent router until you set `enabled = true` in `[intents]`.
- **Whitelist required.** Mnemonic only fires Shortcuts whose names appear in `allowed_shortcuts`. Even if the model hallucinates a name outside the list, it's refused before reaching the OS.
- **No AppleScript, no shell interpolation.** The input is piped to the Shortcut via stdin (`shortcuts run NAME --stdin`). There's no injection surface.
- **Undoable for 5 seconds.** After a fire, the tray menu shows `Undo: <shortcut>` for the configured window. Clicking it runs a paired `undo-<name>` Shortcut if you've defined one.
- **Notes are the source of truth.** A successful fire writes a `↳ Ran shortcut "<name>": <input>` continuation line beneath the bullet. The daily file shows what fired and when — greppable, auditable.

To enable:

```toml
[intents]
enabled = true
allowed_shortcuts = ["create-reminder"]
undo_window_ms = 5000
```

The thought-dump test suite is taken seriously. Phrases like *"I was thinking about reminding Sarah but maybe she already knows"* score as `{tool: "none"}` and produce a plain bullet — no side effect. Validated at 30/30 across hand-labelled transcripts including 15 of the hardest hedged/observational cases that must NOT fire. See `docs/spike/intent/PHASE-0-INTENT-FINDINGS.md` for the methodology.

See the **Intent routing** section in the README for the full setup, including how to build the `create-reminder` Shortcut in Shortcuts.app.

### Other changes

- **`mnemonic doctor`** picks up the new `[intents]` block in config validation.
- **Logs at `~/Library/Logs/Mnemonic/`** rotate at 5 MB, keeping 3 files. No log line ever contains transcribed text or model output.
- **Default config file** now writes `screenshot_combo`, `inbox_dir`, and the `[intents]` block on first launch — matching what the README documents. Existing configs are not modified; missing sections fall back to defaults.

### Configuration additions

All defaults are safe — none of these change v0.2.x behaviour unless you opt in.

```toml
[hotkey]
screenshot_combo = "ctrl+alt+cmd+space"   # set "" to disable

[paths]
inbox_dir = "~/Mnemonic/inbox"            # pending recordings until structuring completes

[intents]
enabled = false                           # opt-in
allowed_shortcuts = []
undo_window_ms = 5000
```

### Breaking changes

None. Existing notes, audio files, and config keep working as before. Upgrade and the new features are dormant until you turn them on.

### Install

```bash
brew tap EduardMaghakyan/tap
brew upgrade --cask mnemonic
```

Or download `Mnemonic_0.3.0_aarch64.dmg` below.

### Requirements

- Apple Silicon Mac (M1 or later)
- macOS 13 Ventura or later
- `llama.cpp` 9050+ (`brew upgrade llama.cpp` if you're below — older bottles silently fail to load the `gemma4` arch)
- 16 GB unified memory minimum; 24 GB more comfortable alongside an IDE + browser
- For the screenshot hotkey: Screen Recording permission (macOS prompts on first use)
- For intent routing: a macOS Shortcut you've named and added to `allowed_shortcuts`
